## Exclusão destrutiva na preparação dos IFs

`scripts/prepare-ifs-reader.mjs` verificava imagens/gabaritos e depois executava `rm` de `prova.pdf` e `gabarito.pdf`, sem mover ou preservar cópia em cache. O teste seguinte tentava ler esses mesmos bytes para conferir a proveniência. Exemplos observados no job da main:

- `public/acervo/ifmt-2025-1/prova.pdf`;
- `public/acervo/ifmt-2026-1/prova.pdf`;
- `public/acervo/ifrs-2025-1/prova.pdf`;
- `public/acervo/ifrs-2026-1/prova.pdf`;
- `public/acervo/ifrn-2023/prova.pdf`;
- `public/acervo/ifrn-2026/prova.pdf`;
- `public/acervo/ifmg-2026-1/prova.pdf`;
- `public/acervo/ifrn-2024/prova.pdf`.

A correção torna esse validador não destrutivo: as imagens continuam verificadas e os PDFs oficiais permanecem disponíveis para conferência. O teste de regressão executa o script real duas vezes em diretório temporário e exige preservação dos bytes da prova, do gabarito e da imagem.

A validação adequada executa o pipeline real antes dos testes; simular apenas o cache COLUNI/IFSC/IFSP não cobria a exclusão dos IFs:

```sh
npm run acervo:prepare
npm test
npm run typecheck
npm run lint
npm run build
```

O CI completo dessa sequência deve terminar antes de declarar a integração validada.

## Migrações de dependências independentes

O TypeScript 7 exige uma estratégia de compatibilidade com o parser de lint; desligar o lint não resolve a incompatibilidade. A versão publicada de `typescript-eslint` consultada foi 8.72.2, ainda com limite `<6.1.0`.

O Stripe 23 exige adaptar a leitura do período da assinatura para a API vigente e testar expiração/concessão de acesso. A atualização automática do pacote não migra o webhook. A falha de Vercel nesse PR corresponde ao erro de compilação registrado no TypeScript.

Os PRs #103/#104/#105 também precisam receber a main corrigida para gerar novos checks. Seus resultados históricos vermelhos não são reavaliados por um merge feito apenas na base.
